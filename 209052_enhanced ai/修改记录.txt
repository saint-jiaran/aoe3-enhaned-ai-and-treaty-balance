一、卡牌发送逻辑（game\ai\core\aihccards.xs）
--------------------------------------------------------------------------------
修改内容：
    将发卡逻辑改为「只有在所有一次性/有限卡片全部发完后，才发送无限卡片」。

实现位置：
    aiHCCards 卡牌选择逻辑中，引入 isInfiniteCard() 判断：
    - 主循环只考虑一次性（有限）卡片：if (isInfiniteCard(deck, i) == false)
    - 无限卡片被单独追踪为 bestInfiniteCard / bestInfiniteCardValue
    - 当没有一次性卡片可发时，才回退选择最好的无限卡片
      （bestCard = bestInfiniteCard）

    相关代码区域：aihccards.xs 约 2943~3930 行附近。

    补充修复（无限卡仍可能提前发送的问题）：
       原实现只在「当前可发送的一次性卡」里判断 foundFiniteCard，导致那些
       时代门控（age 未到）的一次性卡被跳过，从而在一次性卡尚未发完时
       提前发送了无限卡。现新增 hasRemainingFiniteCard() 辅助函数，在回退到
       无限卡之前，先检查卡组中是否仍存在「未发送的一次性卡」（发送次数 > 0）：
       - 存在 → 继续等待，不发送无限卡（bestCard 保持 -1）
       - 不存在 → 才回退到 bestInfiniteCard
       （USA / 墨西哥额外检查 aiHCGetExtendedDeck() 扩展卡组）

七、非洲文明 deField 建造修复（game\ai\core\aibuildings.xs）
--------------------------------------------------------------------------------
修改内容：修复非洲文明（豪萨 / 埃塞俄比亚）AI 不建造 deField 的问题。

    背景：非洲文明的农田与种植园都是 deField，其选址依赖谷仓（deGranary）：
    selectFieldBuildPlanPosition() 会在主基地 200 米内寻找谷仓，找不到就把
    农田计划挂起（return false），等谷仓建好后再放。一旦谷仓迟迟未建成，
    农田计划就会一直排队，导致非洲 AI 长期不建农田。

    1) 修复 selectGranaryBuildPlanPosition() 的作用域 bug
       huntableUnitID 原本声明在 if 块内部，却在块外（函数末尾）被引用，
       会读到未定义变量。现将 int huntableUnitID = -1; 提升到函数作用域，
       保证谷仓缓冲间距（靠猎物 5.0 / 农田 15.0）判断正确。

    2) selectFieldBuildPlanPosition() 增加基地兜底选址
       当 200 米内找不到可用谷仓时，除尝试补建一座谷仓外，不再返回 false
       让农田计划无限排队，而是直接把农田放到主基地（aiPlanSetBaseID）并
       返回 true。这样非洲文明的 deField 一定能被建造出来，不再卡在谷仓后。

十二、修复无限卡在一次性卡发完后不再发送的问题（game\ai\core\aihccards.xs）
--------------------------------------------------------------------------------
问题：第一节加的判断函数 hasRemainingFiniteCard 用了 aiHCCardsGetCardCount(card) > 0
来判定"还有一次性卡未发"，但 aiHCCardsGetCardCount 返回的是该卡在卡片池里的
静态可发送次数（一次性卡恒 > 0，发完也不会变成 0），于是这个函数永远返回 true，
导致一次性卡全部发完后无限卡也被永久挡住、一张都不发。

修改：
    1) hasRemainingFiniteCard 改用 aiHCDeckCanPlayCard(i, extended) 来判断
       "这张一次性卡现在还能不能发"（= 未发送 且 已达到所需时代），并跳过无限卡
       （用 isInfiniteCard 识别）。函数签名加了一个 extended 参数，用于区分
       默认卡组 / 美国、墨西哥的扩展卡组。
    2) 调用处同步传入 extended（默认卡组 false、扩展卡组 true）。

说明：
    - 修复后行为：只要还有"当前可发的一次性卡"就优先发一次性卡；一次性卡全部
      发完后回退到发送最优的无限卡。
    - 时代未到的后续一次性卡（比如帝国时代才解锁的卡）不会再阻塞当前时代的
      无限卡；等升到对应时代后那张一次性卡会重新进入可发池、自动抢占优先级。
